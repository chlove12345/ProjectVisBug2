# VisBug2 功能设计规范

> 适用范围：新增或调整 VisBug2 功能时，判断功能是否需要、应放在哪、如何进入和退出、怎样反馈结果。以 2026-10-30 工作区源码中的产品结构为主，外部可用性原则为辅。本文给出设计决策规则，不要求每个小改动都生成额外提案，也不授权扩大当前开发任务范围。

## 1. 当前产品的功能入口

| 入口 | 当前承担的职责 | 源码依据 |
| --- | --- | --- |

## 2. 先确定功能属于哪一类

| 功能特征 | 首选位置 | 设计理由与边界 |
| --- | --- | --- |
| 高频、需持续作用于页面的编辑模式 | 左侧工具栏，靠近已有同类工具 | 用户要反复进入，并需要看到当前模式；新增图标必须有名称、说明和退出方式。不要仅为偶尔使用的命令扩充主栏。 |
| 只对当前选中元素执行一次 | 选中元素旁的操作菜单 | 入口与作用对象相邻；无有效选择时不显示或明确禁用。执行后不应意外切换正在使用的工具。 |
| 不常用、适合输入参数或命令的进阶操作 | 搜索/命令入口 | 保持主栏精简；名称和提示应让用户知道命令能做什么，不能让高频核心功能只能靠记命令使用。 |
| 跨工具、跨页面持续生效的偏好 | 优先放设置面板 | 例如语言；应明确当前值、修改后的生效时机与保存范围。现有扩展右键菜单里的偏好可保留，新增入口时先避免同一设置出现含义不一致的双入口。 |
| 只读的元素信息或临时测量结果 | 元素附近的浮层或覆盖层 | 让结果与对象保持关联，并避免遮挡目标；不把信息型功能做成必须确认的对话框。 |

以上是放置顺序，不是自动重排现有入口的理由。若一个功能同时符合多类，先看用户最常从哪里开始、作用对象是什么，再选一个主入口；其他入口只作为必要的快捷方式。

## 3. 功能流程应回答的七个问题

1. **用户要完成什么？**写成可观察的结果，例如“对所选元素导出 PNG”，不要只写“增加导出按钮”。
2. **何时可用？**明确是否需要选中元素、当前工具、权限或有效输入；无条件时如何提示，而不是点击后才静默失败。
3. **从哪里进入？**按上表选主入口，说明与相邻功能的关系。入口名称应描述用户目标，而非内部模块名。
4. **进入后是什么状态？**持续工具显示选中态；一次性动作显示忙碌和结果；设置显示当前值。切换工具、关闭面板或失去选择时状态应可预期。
5. **怎样完成、取消或恢复？**可撤销的页面编辑接入现有撤销/重做；未提交的操作可取消；不可逆或大范围操作在执行前明确影响。
6. **结果怎样反馈？**成功、失败、空结果和处理中都要有与动作相关的反馈。日常操作避免无必要的阻塞式弹窗；错误信息说明下一步能做什么。
7. **会影响网页吗？**VisBug 叠加在用户页面上；检查快捷键、点击、滚动、层级、焦点和清理逻辑是否侵入网页原有交互。

## 4. 交互与位置的具体约定

- **模式与动作分开。**工具栏适合“选中后持续生效”的模式；选中菜单或命令适合“执行一次”的动作。工具切换需停用上一功能，释放其监听器和临时 UI；动作完成后不应留下无意义的激活状态。
- **选择是上下文。**依赖元素的操作应在用户选中后就近出现。选择清空、元素移除或位置变化时，菜单和覆盖层应隐藏或更新，不能指向过期对象。
- **设置与编辑分开。**语言等全局偏好在设置弹窗中修改并立即给出可见结果；打开设置不改变当前工具，弹窗内的键盘操作不应触发工具快捷键。弹窗可关闭并将焦点还给入口，保存范围需与用户预期一致。
- **帮助就近、按需出现。**首次接触可从图标说明了解作用和快捷键，复杂操作再提供分步说明；不要让使用者必须记住快捷键或读长篇文档才能开始。
- **覆盖层不喧宾夺主。**优先显示当前操作需要的测量值、位置或错误；保持与目标的空间关联，接近视口边缘时换边或收起。交互控件不能只在悬停时可用。
- **异常可恢复。**输入无效、找不到元素、权限不足或插件失败时，保留用户已完成的工作，给出具体原因和可采取的动作；不要仅写“失败”。

## 5. 评估新功能是否符合用户体验

设计评审时，记录下面五项即可；简单改动可直接用一两句话回答，不额外创建流程文档：

| 问题 | 判断方法 |
| --- | --- |
| 是否容易找到？ | 不知道快捷键的用户能否从现有入口及名称推断位置。 |
| 是否容易理解？ | 看入口、说明和当前状态，能否预测点击后的结果。 |
| 是否容易控制？ | 能否退出、取消或撤销，且不会意外改变其他内容。 |
| 是否容易看见结果？ | 操作对象、进行中状态、成功/错误反馈是否就近且及时。 |
| 是否与现有体验一致？ | 入口位置、视觉状态、键盘操作、文案与同类工具是否一致。 |

例如：语言切换属于跨工具偏好，放设置；导出依赖所选元素，放选中菜单；新布局编辑模式若需要连续调整，才考虑加到主工具栏。具体实现仍以单次需求为边界。

## 外部参考

- [Nielsen Norman Group：10 Usability Heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/)：状态可见、用户控制、一致性、识别优于回忆、错误预防与恢复。
- [WCAG 2.2](https://www.w3.org/TR/WCAG22/)：键盘可操作、焦点可见、标签/说明、悬停内容和目标尺寸等要求。
- [WAI-ARIA Authoring Practices：Menu Button](https://www.w3.org/WAI/ARIA/apg/patterns/menu-button/)：菜单按钮的语义、键盘进入/退出和焦点返回。
